¿Qué es y para qué sirve?

Este conector permite al agente de Ruvic gestionar trabajo en Azure DevOps: crear work items, consultar el estado de la ejecución más reciente de un pipeline, y agregar comentarios a un work item existente.

Este conector escribe datos reales create_work_item y add_comment crean registros reales en el proyecto configurado. No hay modo dry-run.
OperaciónQué hace
azure_devops.create_work_itemCrea un work item (Task, Bug, User Story, etc.)
azure_devops.get_pipeline_statusConsulta el estado de la última ejecución de un pipeline
azure_devops.add_commentAgrega un comentario a un work item existente

Prerrequisitos

  • Una organización y proyecto de Azure DevOps ya creados.
  • Permiso para generar un Personal Access Token en esa organización.

Configuración en el fabricante

  1. Generá un Personal Access Token dedicado.

    En Azure DevOps → User Settings → Personal Access Tokens → New Token.

  2. Asigná los scopes mínimos necesarios.

    Marcá "Work Items" en modo Read & Write, y "Build" en modo Read. No marques scopes de administración de proyecto u organización.

  3. Anotá los identificadores necesarios.

    Nombre de la organización, nombre del proyecto, y el Personal Access Token generado (solo se muestra una vez).

Permisos requeridos

PermisoPara qué sirve
Work Items (Read & Write)Crear work items y agregar comentarios
Build (Read)Consultar el estado de pipelines
Nota No se otorgan scopes de administración de proyecto ("Project and Team") ni de organización ("Graph", "Identity").

Configuración en Ruvic

Entrá a Settings → Conectores, buscá Azure DevOps y pulsá Configurar. Completá Organización, Proyecto y Personal Access Token.

Probar conexión — la plataforma consultará los metadatos del proyecto para confirmar credenciales.

Verificación

  1. Test de conexión exitoso.

    "Probar conexión" debe responder con éxito.

  2. Prueba mínima con el agente.

    Pedile:

    "Creame un Task de prueba llamado 'Validación Ruvic'."

    El agente debe confirmar la creación y devolver el ID del work item.

Solución de problemas

Mensaje / síntomaCausa probable y solución
"Credenciales inválidas o PAT sin permiso suficiente"PAT vencido/rotado, o falta el scope "Work Items" o "Build" necesario.
"Recurso no encontrado"Nombre de organización o proyecto mal escrito, o el work item/pipeline indicado no existe en ese proyecto.
"No se pudo conectar a Azure DevOps" (timeout)Nombre de organización incorrecto, o restricciones de red que bloquean a Ruvic.
"El pipeline no tiene ejecuciones registradas"El pipeline nunca se ejecutó, o el ID de pipeline es incorrecto.

Preguntas frecuentes y notas de seguridad

¿El agente puede administrar el proyecto o la organización?

No. El PAT solo tiene permisos sobre work items (lectura/escritura) y pipelines (lectura); el conector no expone ninguna operación de administración.

¿Dónde queda guardado el Personal Access Token?

Como secreto en el almacén de credenciales de la plataforma. La interfaz nunca vuelve a mostrarlo.

Rotación de credenciales

Los PAT de Azure DevOps expiran según la fecha configurada al crearlos (máximo 1 año). Generá uno nuevo antes del vencimiento y actualizalo en el formulario.

¿Qué hago si el Personal Access Token se compromete?

  1. Revocá el PAT comprometido en Azure DevOps → User Settings → Personal Access Tokens.
  2. Generá uno nuevo y actualizalo en el formulario.
  3. Revisá el historial de auditoría del proyecto por actividad inesperada.
Buenas prácticas Usá un PAT dedicado con scopes mínimos y expiración corta; nunca uses un PAT con permisos de administración global; y confirmá con el usuario antes de crear work items o comentarios contra un proyecto de producción.
